# Tsumugi（つむぎ）使い方ガイド

Tsumugi は、複数の AI コーディングエージェント、シェル、Neovim を一つの画面で使うアプリです。
エージェントへの依頼は下側の Neovim 入力欄に書き、返事や実行状況は上側のコンソールで読みます。

このガイドは Linux 版の標準キー設定を前提にしています。
まず「最初の依頼を送る」まで試せば、基本の流れをつかめます。

## 1. 起動する

### 今の環境で起動する

ソースからビルドしたアプリは、ターミナルから次を実行できます。

```sh
~/workspace/tsumugi/target/debug/tsumugi
```

ソースからビルドして起動する場合はこちらです。

```sh
cd ~/workspace/tsumugi
cargo run --locked -p tsumugi --bin tsumugi
```

インストール後のコマンド名は `tsumugi`、アプリランチャーでの名前は `Tsumugi` です。
インストール方法は [README](../README.md#run-on-linux) にあります。

ウィンドウの初期配置は、お使いのデスクトップやウィンドウマネージャーの設定に従います。

### もう一つ画面を開く

```sh
~/workspace/tsumugi/target/debug/tsumugi --new-window
```

同じ作業やセッションを別のウィンドウから見られます。

## 2. 画面の見方

```text
┌──────────────────────────────────────────────────────────────┐
│ Tsumugi ▼       作業場所・状態                   ⚙ ウィンドウ操作 │
├───────────────┬─────────────────────────────┬────────────────┤
│ 左：ツリー      │ 中央：タブ                    │ 右：詳細パネル    │
│               │ ┌─────────────────────────┐ │                │
│ プロジェクト    │ │ エージェントのコンソール     │ │ 状態・変更・履歴  │
│ ├ Files       │ │ 返事や実行状況が出る         │ │ タイムラインなど  │
│ ├ Sessions    │ ├─────────────────────────┤ │                │
│ └ Terminals   │ │ 依頼を書く Neovim 入力欄    │ │                │
│               │ └─────────────────────────┘ │                │
└───────────────┴─────────────────────────────┴────────────────┘
```

| 場所 | 何をするところか |
| --- | --- |
| 左のツリー | プロジェクト、ファイル、セッション、シェルを選ぶ |
| 中央のタブ | エージェント、シェル、ファイルを開く |
| セッションの上側 | エージェントの返事や、許可を求める画面を見る |
| セッションの下側 | 次に頼む内容を Neovim で書く |
| 右の詳細パネル | 作業状況、コード変更、履歴、関連ファイルなどを確認する |
| 左上の `Tsumugi ▼` | アプリのメニューを開く |
| 上部の歯車 | 設定画面を開く |

**セッション**は、エージェントとの一つの会話・作業です。
同じプロジェクトでも、実装用と調査用など、複数のセッションを作れます。
**プロファイル**は、使うエージェント、ログイン先、モデルなどをまとめた起動設定です。

画面左下の表示は、現在どこにキーが送られるかを示しています。
操作が分からなくなったら、まずその表示と `F1` のキーヘルプを確認してください。

## 3. 最初の依頼を送る

### ① 使うエージェントを確認する

Tsumugi は、インストール済みの `claude`、`codex`、`pi`、`opencode` を起動します。
普段ターミナルで使っているエージェントを、最初の一つとして選ぶと始めやすいです。

1. 上部の歯車で **Settings** を開きます。
2. **Agents** から、使いたいエージェントのプロファイルを選びます。
3. **Login** を確認します。

| Login の選択肢 | 意味 |
| --- | --- |
| `Your terminal's` | 普段ターミナルで使っているログイン・設定を使う |
| `This profile's own` | このプロファイル専用のログイン・設定を使う |

最初は `Your terminal's` を使うと、既存の環境を利用できます。
ログインが必要なら **Open login terminal** を開き、そのエージェントの案内に従います。
エージェントが見つからない場合は、インストール先やプロファイルの起動コマンドを確認してください。

### ② 作業するフォルダーを選ぶ

1. `Ctrl+Shift+p` を押します。
2. 作業したいフォルダーを一覧から選びます。入力すると候補を絞れます。
3. 矢印キーなどで移動し、`Enter` で選びます。

目的のフォルダーが一覧にない場合は、選択画面で `Ctrl+f` を押すとフォルダーをたどれます。
一覧を閉じるときは `Esc` です。

フォルダーを選ぶと **New session** が開きます。この段階では、まだ依頼を送っていません。
表示されている作業パス、プロファイル、モデル、権限設定を確認します。

特定のプロジェクトを使わずに相談するなら、左上のメニューから
**Session → New Scratch Session** を選べます。

### ③ 下の入力欄に依頼を書く

下側の入力欄に移動して書きます。通常モードなら、Neovim と同じく `i` で入力を始めます。
例えば、最初は次のような依頼にすると動きを確認できます。

```text
name: プロジェクトの確認
このプロジェクトの構成と、開発時によく使うコマンドを説明してください。
この依頼ではファイルを変更しないでください。
```

先頭の `name:` はセッション名です。この行はエージェントへの依頼から取り除かれます。
省略して普通の依頼だけを書いても使えます。

### ④ `Ctrl+Enter` で送る

入力欄に依頼を書いたら **`Ctrl+Enter`** を押します。
エージェントが起動し、上側のコンソールに返事や進行状況が表示されます。

続けて頼みたいことも、同じセッションの下側に書いて `Ctrl+Enter` で送ります。
送信後は入力欄が空の通常モードになるので、次の文章を書くときは `i` を押します。

入力モードの `Enter` は改行です。依頼の送信には `Ctrl+Enter` を使います。

## 4. 入力先を切り替える

ここが最初に迷いやすいところです。

| 今したいこと | 操作 |
| --- | --- |
| エージェントに文章で依頼する | 下側の入力欄で書き、`Ctrl+Enter` |
| エージェントの許可・選択画面に答える | その画面に従い、選択キーや `Enter` を押す |
| シェルでコマンドを実行する | シェルのタブでコマンドを書き、`Enter` |
| ファイルを編集する | Neovim のタブで通常どおり編集する |

許可や選択を求める画面が出ている間は、キー入力はその回答に使われます。
その前に下側へ書いていた文章は、回答の後に使えるよう残ります。

### 画面内の移動

`Ctrl+q` を押して離し、続けて方向キーに相当する文字を押します。
例えば `Ctrl+q` → `j` は下、`Ctrl+q` → `k` は上です。

| キー | 移動先 |
| --- | --- |
| `Ctrl+q h` | 左。中央からならツリーへ |
| `Ctrl+q j` | 下。コンソールからなら入力欄へ |
| `Ctrl+q k` | 上。入力欄からならコンソールへ |
| `Ctrl+q l` | 右。中央からなら詳細パネルへ |

`Ctrl+w` は Neovim など中のプログラムが使います。
Tsumugi の画面間移動は `Ctrl+q` から始めます。

### エージェントの画面へ直接キーを送りたいとき

コンソールに移動して `Ctrl+g` → `i` を押すと、キーを直接エージェントへ送るモードになります。
`Esc` で戻ります。画面左下に `PASS` と出ている場合は、このモードです。

通常の依頼文を書くときは、このモードを抜けて下側の入力欄を使ってください。

### 長い出力を Vim の操作で読みたいとき

`Ctrl+q` → `[` で、コンソールを Neovim の操作で読むモードに入ります。
移動・検索・選択・ヤンクができ、`q` でライブ表示へ戻ります。

## 5. 普段の zsh を使う

プロジェクトやセッションを選んだ状態で **`Ctrl+Shift+s`** を押すと、その作業場所にシェルを開きます。
左のツリーにフォーカスがある場合は `$` でも開けます。

普段のログインシェルを起動するので、zsh を使っているアカウントでは `.zshrc`、エイリアス、既存プラグインを利用します。
シェルのタブでは、そのままコマンドを書いて `Enter` で実行できます。

```sh
git status
```

起動コマンドや環境変数を変えたい場合は **Settings → Programs → Shell** で設定します。
標準の動作でよければ空のままで使えます。

## 6. 普段の Neovim でファイルを編集する

### ツリーからファイルを開く

1. 左のツリーで、プロジェクトの **Files** を展開します。最初は折りたたまれています。
2. 編集したいファイルを選び、`Enter` で開きます。
3. Neovim に開かれたファイルを、いつもどおり編集します。

Markdown、画像、PDF などは、種類に応じてビューアーに開かれます。
Markdown などの文書を編集するときは、ビューアーで `e`、または `Ctrl+q` → `e` で Neovim に切り替えます。

### 作業フォルダーに Neovim を開く

**`Ctrl+Shift+e`** で、作業場所に Neovim を開けます。
左のツリーにフォーカスがある場合は `e` でも開けます。
その後は `:edit README.md` など、普段の Neovim の操作でファイルを開けます。

| Neovim のコマンド | 操作 |
| --- | --- |
| `:edit README.md` | 作業フォルダーの README.md を開く |
| `:w` | 保存する |
| `:q` | 現在の Neovim ウィンドウを閉じる |

ローカルのファイル編集タブは、普段の Neovim 設定を読み込んで GUI 表示します。
使う実行ファイル・起動引数・環境変数は **Settings → Programs → Neovim** で変更できます。
シェル内で `nvim` と打って起動した場合は、そのシェルの中で通常のターミナル表示になります。

依頼を書く下側の Neovim と、ファイル編集用の Neovim は設定が別です。
下側の入力欄まで普段の設定に変わるわけではありません。

## 7. セッションとタブを使い分ける

### 同じプロジェクトで、別の依頼を始める

**`Ctrl+Shift+t`** で、選択中の作業場所に新しいセッションの下書きを開きます。
そこでプロファイルと依頼文を選び、`Ctrl+Enter` で始めます。
既存のセッションへ追加質問するときは、新規作成せずそのセッションの入力欄を使います。

### タブを切り替える

| キー | 操作 |
| --- | --- |
| `Ctrl+Tab` | 次のタブ |
| `Ctrl+Shift+Tab` | 前のタブ |
| `Ctrl+Shift+1`〜`9` | 中央のタブへ番号で移動。`9` は最後のタブ |
| `Ctrl+Shift+w` | 中央の現在のタブを閉じる |

右の詳細パネルで `Ctrl+Tab` を押すと、詳細パネル内のタブを切り替えます。
タブ名をクリックして選ぶこともできます。

### 画面を分割する

| キー | 操作 |
| --- | --- |
| `Ctrl+q v` | 左右に分割 |
| `Ctrl+q s` | 上下に分割 |
| `Ctrl+q c` | 今いる分割画面を閉じる |

分割直後は同じ内容が両側に表示されます。
片側へ移動してツリーから別のセッションなどを開くと、並べて作業できます。

### ツリーの基本操作

| キー | 操作 |
| --- | --- |
| `j` / `k` | 下 / 上へ移動 |
| `Enter` / `o` / `l` | 選択項目を開く、または展開する |
| `h` | 折りたたむ、または親へ移動 |
| `n` | 選択した場所に新しいセッションを作る |
| `$` | 選択した場所にシェルを開く |
| `e` | 選択した場所に Neovim を開く |
| `x` | 表示を閉じる。実行中のセッションは終了しない |
| `X` | セッション・ターミナルを終了する。確認が出る |

ツリーやタブを右クリックすると、その項目に使える操作も確認できます。

## 8. 閉じる操作と、作業を終了する操作

| 操作 | 実行中の作業 |
| --- | --- |
| タブや分割画面を閉じる | セッションやシェルは動き続ける |
| Tsumugi のウィンドウを閉じる | セッションやシェルは動き続ける |
| ツリーのセッション・ターミナルで `X` | 確認後、そのプログラムを終了する |
| シェルで `exit` | そのシェルを終了する |

一時的に画面を閉じたいだけなら、右上の閉じるボタンやタブの `×` を使えます。
Tsumugi を開き直し、ツリーから同じセッションを選ぶと戻れます。

ローカルのファイル編集用 Neovim も、アプリのウィンドウを閉じただけなら未保存内容を保持します。
ただし、PC の再起動やバックグラウンドのターミナルホストの終了まで耐える保存ではありません。
ファイルの変更は通常どおり `:w` で保存してください。

終了済みの会話を再開したいときは **`Ctrl+Shift+o`** から探します。
履歴や再開の対応範囲はエージェントによって異なります。

## 9. 表示や設定を調整する

| やりたいこと | 場所・キー |
| --- | --- |
| 設定を開く | 歯車、または `Ctrl+Shift+,` |
| 左のツリーを表示・非表示にする | `Ctrl+Shift+b` |
| 右の詳細パネルを表示・非表示にする | `Ctrl+Shift+d` |
| エージェントやログインを変える | Settings → Agents |
| シェル・ファイル編集用 Neovim を変える | Settings → Programs |
| 文字や UI の大きさを調整する | Settings → Window の自動スケール・Zoom |
| キー割り当てを確認・変更する | Settings のキー設定 |
| 今いる場所のキーを確認する | `F1` |

4K などの高解像度画面では、標準で自動スケールが働きます。
Hyprland の「画面の80%で開く」設定はウィンドウの外寸、Tsumugi の Zoom は中身の表示倍率です。

右の詳細パネルは、標準では次のように使えます。配置は設定で変更できます。

| タブ | 確認できるもの |
| --- | --- |
| Overview | セッションの状態や作業の概要 |
| Code | コード変更や履歴 |
| Timeline | エージェントが記録したタスク・進捗 |
| Conversation | 依頼、メッセージ、関連セッションなど |
| Resources | 関連するファイル、リンク、画像など |

## 10. 困ったとき

### 文字を打っても依頼欄に入らない

画面左下の入力先を確認してください。
`PASS` なら `Esc` で抜け、コンソールから `Ctrl+q` → `j` で下側へ移動して `i` を押します。
エージェントの許可画面が出ているなら、まずその質問に答えます。

### プロジェクトを開いたのに動かない

**New session** は送信前の下書きです。
エージェントを選び、下側に依頼文を書いて `Ctrl+Enter` を押すと始まります。

### エージェントにログインしているのに、未ログインと表示される

Settings → Agents で、そのプロファイルの **Login** を確認してください。
`This profile's own` は普段のターミナルとは別のログインです。
普段のログインを使うなら `Your terminal's` を選びます。

### タブを閉じた作業へ戻りたい

左のツリーの **Sessions** や **Terminals**、編集していたファイルの行から開き直します。
タブの `×` は、動いているプログラムを終了する操作ではありません。

### zsh がプラグインを新しく入れようとする

通常起動では、既存の環境を使います。
起動時に `HOME`、`ZDOTDIR`、`XDG_DATA_HOME` などを変更していないか、
Settings → Programs → Shell の環境変数を確認してください。

作業のまとまりだけを分けたい場合は、保存先の環境変数を変えず、次のように起動できます。
同じ名前のインスタンスを開くと、そのインスタンスの作業へ戻れます。設定やキー割り当ては共有です。

```sh
~/workspace/tsumugi/target/debug/tsumugi --instance playground
```

### Neovim の GUI が付かず、ターミナル表示になる

リモート編集や、GUI 接続先を持たない既存の編集タブは、ターミナル表示を使います。
Neovim がエラーの「Enter を押してください」で止まっている場合も、先にその表示へ応答してください。
